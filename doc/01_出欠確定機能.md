# 出欠確認機能設計書
## 目的
出欠確認機能は、実際の活動（Schedule）に対して、団員が「出席」「欠席」のいずれかを選択できる。確定した出欠は、ログとして保存され、出席率の計算や、活動の振り返りに利用される。
また、団員の適切な活動への参加を促す目的もある。

## 機能概要
### 出欠入力
- 出欠の入力は、権限をもつユーザーが行う
- 出欠の入力は、権限を持つ担当者が、団員全員の出欠を一括で入力する。
- 入力は、ラジオボタンで、「0: 出席」「1: 欠席」「2: 休団」を選択する形式とする。
- 備考欄を設け、欠席理由や特記事項を入力できるようにする。
- 出欠入力をする活動日が、休団期間に該当する場合は、出欠入力を「休団」として自動的に設定する。
- 休団中に出席するケースも考慮し、休団期間中の活動に対しては、出欠入力を「休団」として自動的に設定するが、担当者が必要に応じて「出席」や「欠席」に変更できるようにする。

### 基本仕様
- 出欠の入力は、活動日ごとに行う。
- 出欠の入力は、活動日が過ぎた後も可能とする。
- 入力可能になるのは、活動当日の1時間前からとする。

### 権限
- 閲覧 : 全ユーザー
- 入力 : 担当者のみ
- 編集 : 担当者のみ
- 削除 : 担当者のみ

## データ保存
- 出欠のデータは、ScheduleLogテーブルに保存する。

## テーブル設計
ScheduleLog
| カラム名 | データ型 | 説明 |
| --- | --- | --- |
| id | uuid | 主キー |
| date | date | 日付 |
| start | time | 開始時刻 |
| end | time | 終了時刻 |
| title | varchar(255) | 活動名 |
| place | varchar(255) / null | 場所 |
| note | text | 活動内容 |
| music | varchar | リスト形式の一覧 |
| attendances | json | 出欠の情報をJSON形式で保存 |

※attendances以外はreadonlyとする。
- attendancesのデータ構造
値は、Attendanceモデルの出欠の選択肢に対応させるが、出席、欠席、休団の3種類のみ保存する。
| 値 | 状態 |
| --- | --- |
| 1 | 出席 |
| 4 | 欠席 |
| 6 | 休団 |

]
